# Лист и свет · демо консультанта

Консультант компании по аренде растений. Компания и ее справочник вымышлены по условию тестового. Агент находит ответ по смыслу, учитывает предыдущее сообщение и может позвать менеджера по прямой просьбе. После имени и телефона в тестовой СРМ появляются причина обращения и переписка. Дальше сообщения получает менеджер, его ответ возвращается в тот же чат.

[Видео работы](demo.mp4)

## Запуск

Проверено на Python 3.12. Для первого запуска загрузите локальную модель. Дальше приложение работает без ключей и доступа в интернет.

```bash
python -m pip install -r requirements-semantic.txt
python -m demo.prepare_model
python -m demo --semantic
```

Откройте адрес `UI`, который выведет команда. По умолчанию выбирается свободный порт. Для постоянного адреса укажите `--port 8765`. Второй локальный порт занимает API СРМ. Заявки хранятся в `data/leads.sqlite3`. Для нового набора данных запустите с `--db data/second-demo.sqlite3`.

Запуск `python -m demo` включает поиск по ключевым словам и подходит для быстрой проверки чата и СРМ без установки пакетов.

## Что проверить в чате

1. Спросите «А поливать самим или вы приезжаете?», затем «А как часто?». Во втором ответе бот назовет периодичность, а запись справочника можно открыть под сообщением.
2. Спросите «Можно оплатить по счету от юрлица?». Агент предложит менеджера, потому что в справочнике нет условий такой оплаты.
3. Напишите «Позовите менеджера, пожалуйста». Агент запросит контакты и будет отвечать на дополнительные вопросы, пока они не заполнены.
4. Отправьте `Анна`, затем `+7 900 000-00-01`. После второго сообщения в СРМ появятся заявка, вопрос про счет и предыдущие реплики.
5. Откройте переписку в СРМ и напишите в чат `Могу прислать фото переговорной?`. Реплика появится у менеджера. Ответьте из СРМ и проверьте, что ответ появился слева в исходном чате.
6. Обновите страницу. Сохранятся одна заявка и переписка с ответом менеджера.

```bash
python -m unittest discover -s tests -v
```

## Как это устроено

Модель [multilingual-e5-small](https://huggingface.co/Xenova/multilingual-e5-small) строит векторы вопроса и записей из `demo/faq.json`. Если в сообщении есть отсылка к прошлому вопросу, агент проверяет также формулировку с контекстом. По близости выбираются записи. Для коротких уточнений у некоторых записей есть отдельный ответ с нужной частью факта. Типовые темы за пределами справочника используются как дополнительная проверка. Если подходящих сведений нет, агент предлагает подключить сотрудника.

Прямая просьба о менеджере обрабатывается отдельной веткой. Цитата, пример, отмена и условная просьба ее не запускают. Имя и телефон обрабатываются локально. Запись заявки и перенос последних сообщений вместе с подтверждением передачи выполняются одной транзакцией через отдельный HTTP API СРМ. Ключ API создается при старте. Привязка к исходному диалогу сохраняется в SQLite. Пока диалог у менеджера, входящие сохраняются без вызова поисковой модели. Повторы с тем же ключом сообщения считывают уже сохраненный результат.

Этот сценарий вырос из проекта S-GAS. В [публичном кейсе](https://vladexecute.ru/cases/sgas-omnichannel-consultant/) виден пример из рабочего контура Битрикс24, где ответ менеджера возвращается в Telegram. В тестовом стенде роль менеджера играет панель локальной СРМ. Она доступна на том же локальном адресе для проверки обеих сторон диалога.

Для выбора источников можно подключить OpenAI-совместимую модель через `DEMO_MODEL`, `DEMO_MODEL_BASE` и `DEMO_MODEL_TOKEN`. Она получает вопрос и элементы справочника и возвращает их идентификаторы. Адаптер проверен с локальной Qwen2.5-1.5B через llama.cpp. На пяти пробных вопросах Qwen ошиблась с перефразированным вопросом об уходе и подобрала лишний источник к составному вопросу. Для видео выбрал режим `--semantic`, который прошел эти сценарии.

# Лист и свет · демо консультанта

Консультант компании по аренде растений. По условию тестового компания и ее справочник вымышлены. Агент находит ответ по смыслу вопроса, учитывает предыдущее сообщение и показывает, из каких записей взял факты. После имени и телефона он отправляет в тестовую СРМ заявку с описанием запроса. Панель справа читает сохраненную запись через API.

[Видео работы](demo.mp4)

## Запуск

Проверено на Python 3.12. Для первого запуска загрузите локальную модель. Дальше приложение работает без ключей и доступа в интернет.

```bash
python -m pip install -r requirements-semantic.txt
python -m demo.prepare_model
python -m demo --semantic
```

Откройте адрес `UI`, который выведет команда. По умолчанию выбирается свободный порт. Для постоянного адреса укажите `--port 8765`. Второй локальный порт занимает API СРМ. Заявки хранятся в `data/leads.sqlite3`. Для нового набора данных запустите с `--db data/second-demo.sqlite3`.

Запуск `python -m demo` включает поиск по ключевым словам и подходит для быстрой проверки чата и СРМ без установки пакетов.

## Что проверить в чате

1. Спросите «Сотрудникам придется самим следить за грунтом?», затем «С какой периодичностью?». Агент найдет правила ухода и учтет предыдущий вопрос.
2. Спросите «Сколько будет стоить аренда и как часто приходит специалист?». Под ответом будут две записи справочника.
3. Спросите «А можно внести предоплату картой?». В справочнике нет сведений об оплате картой, агент предложит уточнить у специалиста.
4. Отправьте `Нужны 6 растений в офис на Арбате. Меня зовут Анна.`, затем `+7 900 000-00-01`. После второго сообщения в СРМ появятся имя, телефон и запрос.
5. В том же диалоге отправьте `Анна +7 900 000-00-01` и обновите страницу. Останется одна сохраненная заявка.

## Как это устроено

Модель [multilingual-e5-small](https://huggingface.co/Xenova/multilingual-e5-small) строит векторы вопроса и записей из `demo/faq.json`. Когда в сообщении есть отсылка к прошлому вопросу, агент оценивает также формулировку с контекстом. По близости выбираются записи, а в ответ попадают их исходные формулировки. Типовые темы за пределами справочника используются как дополнительная проверка. Если подходящей записи нет, агент сообщает об этом.

Имя и телефон обрабатываются локально. Агент запрашивает недостающее поле и получает подтверждение сохранения через отдельный HTTP API СРМ. Ключ создается при старте. Повтор с теми же контактами в одном диалоге использует тот же ключ заявки. Правило уникальности закреплено в SQLite.

Для выбора источников можно подключить OpenAI-совместимую модель через `DEMO_MODEL`, `DEMO_MODEL_BASE` и `DEMO_MODEL_TOKEN`. Она получает вопрос и элементы справочника и возвращает их идентификаторы. Адаптер проверен с локальной Qwen2.5-1.5B через llama.cpp. На пяти пробных вопросах Qwen ошиблась с перефразированным вопросом об уходе и подобрала лишний источник к составному вопросу. Для видео выбрал режим `--semantic`, который прошел эти сценарии.

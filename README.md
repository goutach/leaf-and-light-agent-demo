# Лист и свет · демо консультанта

Консультант вымышленной компании по аренде растений. Агент отвечает по справочнику из восьми записей. После имени и телефона он создает заявку через HTTP API тестовой СРМ. Справа в интерфейсе виден результат чтения из этой СРМ.

[Видео работы](demo.mp4)

## Запуск

Проверено на Python 3.12. Пакеты ставить не требуется.

```bash
python -m demo
```

Откройте адрес `UI`, который выведет команда. По умолчанию выбирается свободный порт. Для постоянного адреса укажите `--port 8765`. Второй локальный порт занимает API СРМ. Заявки хранятся в `data/leads.sqlite3`. Для нового набора данных запустите с `--db data/second-demo.sqlite3`.

## Что проверить в чате

1. Нажмите «Цена» или «Доставка». Под ответом будет указана запись справочника.
2. Спросите «Можно заказать обслуживание аквариума?». Агент ответит, что информации в базе нет.
3. Нажмите «Оставить заявку», отправьте `Анна`, затем `+7 900 000-00-01`. Запись появится в СРМ после второго сообщения.
4. В этом же диалоге отправьте `Анна +7 900 000-00-01`, затем обновите страницу. Прежняя заявка сохранится, дубль не появится.

## Как это устроено

Агент выбирает идентификатор записи из `demo/faq.json`. Текст ответа всегда берется из выбранной записи. Если подходящей записи нет, агент сообщает об этом. Из коробки используется поиск по ключевым словам. Имя и телефон обрабатываются локально в ветке заявки. После передачи обоих полей агент получает подтверждение через API СРМ. Повтор с теми же полями в одном диалоге использует тот же ключ записи.

Можно подключить модель с OpenAI-совместимым API. Установите `DEMO_MODEL` с идентификатором модели, `DEMO_MODEL_BASE` с адресом API, включая `/v1` при необходимости, и `DEMO_MODEL_TOKEN` для доступа. Модель получает вопрос и названия записей, возвращает ID. При ошибке запроса срабатывает локальный поиск. Пути записи заявок используют отдельный локальный API с ключом, который создается при старте.
